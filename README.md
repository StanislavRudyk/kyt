# RentCar UA

Статический многостраничный интерфейс на React 18 с API на FastAPI/SQLAlchemy и PostgreSQL в Compose. Production frontend собирается из JSX в отдельный минифицированный файл для каждой страницы; Tailwind CSS генерируется локально, React поставляется production-сборкой. GSAP и Google Fonts остаются внешними ресурсами.

## Визуальная система

- Цвета: графитовый фон `--bg`, поверхности `--surface`/`--surface-raised`, тёплый акцент `--gold`, основной и вторичный текст `--ink`/`--text-secondary`, тонкие границы `--line`.
- Шрифты: Inter для интерфейсного текста, Oswald для крупных заголовков, цен и коротких подписей.
- Ритм: шаги от 4 до 64 px; радиусы 2 px для контролов, 6 px для панелей; спокойные тени только для приподнятых поверхностей.
- Общие компоненты: `.btn` с вариантами primary/dark/ghost, `.field`, `.tile`, `.card-elev`, `.surface-panel` и `.kicker` в `src/index.css`.
- Движение уважает `prefers-reduced-motion`; у видео первого экрана есть локальный постер для медленной загрузки и ошибки воспроизведения.

## Страницы

- `index.html` — главная.
- `Inventory.html` / `catalog.html` — каталог и его алиас.
- `Vehicle.html` / `auto.html` — карточка выбранного автомобиля.
- `Service.html` / `booking.html` — форма заявки на аренду.
- `admin.html` — учебная панель оператора для полного цикла аренды.
- `Financing.html` / `tariffs.html` — тарифная информация.
- `About.html` / `about.html` — страница о компании.
- `contact.html`, `privacy.html`, `contract.html`, `history.html`, `404.html` — контакты, предварительное уведомление об обработке данных, условия, история и ошибка.

API роуты находятся в `backend-python/app/routers`. Создание заявки теперь отправляется в `POST /api/v1/bookings`; сервер проверяет даты и пересечения, рассчитывает сумму и отвечает статусом `pending`. Календарь главной получает данные через `GET /api/v1/availability`.

## Локальный запуск интерфейса

Соберите frontend и запустите сервер из production-каталога:

```bash
npm install
npm run build
python3 -m http.server 8080 --directory dist
```

Для сборки используется Node.js 22 (как в Dockerfile). Backend рассчитан на Python 3.11 и PostgreSQL 16 (как в Compose). API локально запускается через Docker Compose; для него нужны непустые `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` (не короче 16 символов). Учебный сценарий по умолчанию использует помеченные демо-локации; для настоящей компании следует задать и проверить `RENTAL_LOCATIONS`.

Сборка использует `scripts/build.js`, конфигурацию `tailwind.config.cjs` и пишет готовые файлы в `dist/`. Разметка страниц и JSX остаются в корне и `src/`; runtime компиляции Babel и Tailwind Play CDN нет. Без Docker API недоступен, поэтому форма заявки покажет ошибку соединения и не будет изображать успешную отправку.

Для sitemap задайте `PUBLIC_SITE_URL` абсолютным production URL перед сборкой. Netlify передаёт переменную `URL` автоматически; при Docker-сборке можно указать `--build-arg PUBLIC_SITE_URL=https://ваш-домен`. Без известного публичного домена sitemap не создаётся. Динамические страницы авто не включаются в sitemap, поскольку каталог может меняться на сервере.

Сборка создаёт отдельный React-бандл для каждой HTML-страницы, локальную production-версию React и статический Tailwind CSS. Для изображений в WebP создаются варианты по ширине; `SmartImg` выбирает подходящий размер и сохраняет JPG как fallback. Каталог и секции главной страницы совместно используют один запрос списка автомобилей. На главной воспроизводится только активное фоновое видео; видео сервисной секции загружается перед появлением в области просмотра.

В исходном каталоге 22 JPG занимают 1,171,886 байт. Набор 480 px WebP-вариантов занимает 261,272 байта, 800 px — 563,388 байт; браузер загружает один подходящий вариант на изображение, а не все размеры. Пять MP4 занимают около 4.8 МБ на диске. Lighthouse и водопад сетевых запросов здесь не запускались: браузер и доступ к работающему production API недоступны, поэтому задержки API и Core Web Vitals не измерены.

Публичные статические страницы имеют отдельные title/description, canonical и Open Graph metadata. Для URL отдельного автомобиля метаданные уточняются после получения подтверждённой записи API. Sitemap создаётся только при заданном домене. Schema.org-разметка и аналитика намеренно не добавлены: компания, отзывы, тарифные условия и аналитическое согласие требуют подтверждения владельца.

Демо-локации заданы внутри приложения и используются, когда `RENTAL_LOCATIONS` не задан или пуст. Чтобы подменить их, передайте JSON-массив пунктов с полями `id`, `name`, `address`, `city`, `timeZone` (IANA), `vehicleIds`, `openingTime`, `closingTime` и `weekdays` (0 — понедельник, 6 — воскресенье). Даты и часы передаются как местные значения вместе с ID пункта; сервер преобразует их в UTC по часовому поясу пункта и отклоняет несуществующее или двусмысленное время при переходе часов.

## Полный запуск через Docker Compose

Создайте `.env` рядом с `docker-compose.yml` и задайте уникальные значения:

```dotenv
POSTGRES_DB=rentcar_db
POSTGRES_USER=rentcar_user
POSTGRES_PASSWORD=
ALLOWED_ORIGINS=["http://localhost:8080"]
RENTAL_DEFAULT_TIME_ZONE=Europe/Kyiv
RENTAL_LOCATIONS=[]
```

Сгенерируйте уникальный пароль командой `openssl rand -hex 32` и вставьте его в `POSTGRES_PASSWORD`. Не коммитьте `.env` и не передавайте пароль в переписке. Затем запустите `docker compose up --build`. Публичный интерфейс доступен на `http://localhost:8080`, API — через `/api/`; backend и БД доступны только во внутренней сети Compose, документация API отключена. Для production поставьте HTTPS ingress перед Nginx: контейнерный Nginx сам TLS не настраивает.

## Ограничения и незавершённые интеграции

### Учебная симуляция полного процесса

Клиент отправляет заявку через `Service.html`; оператор открывает `/admin.html` и проходит цепочку `pending → confirmed → paid → active → completed`, либо отменяет заявку до оплаты. API проверяет разрешённые переходы и сохраняет аудит событий в `booking_events`. После подтверждения доступен демо-договор, после отметки оплаты — демо-квитанция; оба документа можно распечатать или сохранить в PDF.

Демо-пункты выдачи с вымышленными адресами включены по умолчанию. Демо-ключ панели: `rentcar-demo-admin-course-key`. Оплата не обращается к банку, договор не имеет юридической силы, сведения о пунктах и автомобилях учебные. Панель/ключ предназначены только для курсовой демонстрации, их нельзя публиковать в открытом интернете.

- PostgreSQL — постоянное хранилище API (не только frontend/localStorage). `Vehicle` содержит опубликованные поля авто и дневной/недельный/месячный тариф; отдельной таблицы тарифных сезонов и услуг нет. `User` сейчас создаётся при заявке только из имени, телефона и необязательного email. `Booking` хранит автомобиль/клиента, интервал UTC, снимки адресов/часовых поясов, принятый privacy notice, расчёт и статус. Пункты обслуживания загружаются из `RENTAL_LOCATIONS`, а не редактируются в БД; в заявке остаётся их снимок. Таблицы платежей нет, платежи не принимаются.
- Разрешённые переходы ограничены проверками API и триггером БД; пересечения блокируют `pending`, `confirmed`, `paid` и `active`. Уникальный `Idempotency-Key` предотвращает дубли при повторе, а тот же ключ с другим запросом возвращает 409.
- Панель управляет только жизненным циклом брони. Клиентской авторизации и управления каталогом/тарифами/фотографиями нет; ключ панели учебный и не предназначен для публичного размещения.
- Документы создаются только в виде демонстрационного договора и квитанции по существующей заявке. Платёжной интеграции, банковских транзакций и фискальных документов нет.
- `GET /live` проверяет процесс, `/ready` и `/health` проверяют соединение с БД; healthcheck Compose использует readiness. Это не внешняя система мониторинга и не оповещения.
- Секреты PostgreSQL обязательны в окружении API и не имеют кода по умолчанию. `.env` исключён из Git и Docker build context; перед production проверьте также настройки секретов вашего хостинга. Nginx ограничивает запросы к API и заявкам по IP. На внешнем ingress необходимо включить HTTPS/TLS.
- CORS принимает только указанные точные origins (HTTPS, либо localhost для разработки), credentials отключены, документация FastAPI скрыта. Nginx не публикует API-порты напрямую, ограничивает частоту и размер тела запроса, запрещает отдачу backend/hidden-файлов и выставляет защитные заголовки. FastAPI убирает значения введённых полей из JSON ошибок валидации. UI выводит текстовые данные через React escaping; SVG-иконки являются фиксированным замороженным allowlist. Авторизации и cookie-сессий нет, поэтому пароли/токены не хранятся; строгий CSP пока не настроен из-за inline Babel-приложения и внешних скриптов.
- Создайте ручную резервную копию командой `./scripts/backup-db.sh`; по умолчанию закрытый файл появится в `./backups` (каталог не следует коммитить). Резервируйте копию вне хоста/тома БД и назначьте расписание средствами инфраструктуры. Восстановление в существующую БД заменяет её содержимое: `docker compose exec -T postgres sh -c 'pg_restore --clean --if-exists --no-owner -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < backups/ИМЯ.dump`. Сначала остановите API и проверьте копию на отдельной БД; резервное копирование пока не запускается автоматически и не проверяет возможность полного восстановления.

- Единый формат автомобиля хранится в модели `backend-python/app/models/vehicle.py`, выдаётся схемой `backend-python/app/schemas/vehicle.py` и API `/api/v1/vehicles`; frontend не содержит второго каталога. Категория (`category`) отделена от типа кузова (`bodyType`), который остаётся пустым без подтверждённых данных. `backend-python/app/seed.py` остаётся примерным начальным набором, достоверность машин и тарифов владелец должен подтвердить.
- Seed добавляет автомобили, но не демо-клиентов и не бронирования. В уже созданной БД старые демо-записи автоматически не удаляются.
- Заявка создаётся как ожидающая подтверждения; дальше процесс ведётся через учебную панель оператора. Клиентской авторизации, внешних уведомлений и настоящего подтверждения доступности сотрудником нет.
- Время бронирования хранится в PostgreSQL как timezone-aware UTC интервалы; ID, адреса и зоны пунктов сохраняются снимком в заявке. PostgreSQL exclusion constraint запрещает пересечения для `pending`, `confirmed`, `paid` и `active`; API также сериализует одновременные попытки на одно авто.
- Серверный расчёт использует дневной тариф автомобиля из БД × календарные дни (минимум один день). Скидки, неполные сутки, страховка, доставка, дополнительные услуги и налоги не настроены; сумма предварительная до подтверждения владельцем.
- Каталог фильтрует по марке/модели, категории, топливу, коробке передач, числу мест и дневному тарифу. Фильтр кузова доступен только если API вернёт подтверждённые значения. Сортировка использует цену или год; подтверждённых данных популярности нет.
- Интеграции с Monobank/LiqPay и выдача фискальных документов отключены; демо-договор и квитанция доступны для печати в панели оператора.
- Политика конфиденциальности, юридические условия, отзывы, филиалы, социальные ссылки и часть сервисных обещаний требуют проверки владельцем бизнеса. Не размещайте сайт для реальных клиентов, пока эти сведения и тексты не будут подтверждены.
- Схема БД создаётся через `create_all`; миграции Alembic не подключены. Для существующей БД последовательно примените миграции `001_booking_pickup_time.sql`, `002_vehicle_category_body_type.sql`, `003_rental_locations_and_periods.sql`, `004_booking_integrity.sql`, `005_remove_unused_driver_license.sql`. Миграция 003 интерпретирует старые даты как `Europe/Kyiv`; проверьте допущение и прежние пересекающиеся заявки до применения. Миграция 005 удаляет неиспользуемую колонку водительского удостоверения и содержащиеся в ней значения — заранее сохраните резервную копию и проверьте, что эти данные больше не нужны.

## Проверки

Установите тестовые зависимости API и запустите unit suite:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r backend-python/requirements-test.txt
cd backend-python && python -m pytest -q
```

Тесты покрывают серверную валидацию заявки и тарифа, расчёт суммы, локальное время/DST, свободные интервалы/блокировки, а также миграционные ограничения на пересечение броней и переходы статусов. Они не подменяют проверку конкурентной записи на PostgreSQL: для этого необходима отдельная тестовая БД с применёнными миграциями.

Доступные локальные статические проверки: `npm run build`, `python3 -m compileall -q backend-python/app`, `docker compose config` (последняя требует `.env`). Для проверки после развёртывания выполните `BASE_URL=https://ваш-домен python3 scripts/smoke-test.py`: скрипт проверяет публичные страницы, каталог, пункты обслуживания, доступность, read-only расчёт заявки и ответ 404. Если runner имеет сетевой доступ к API service, задайте также `API_BASE_URL=http://python-api:8000` для liveness/readiness и связи с БД. Он работает только с чтением, намеренно не создаёт клиентские заявки и не инициирует оплату.

Проверка актуальных Chrome/Firefox/Safari, реальных мобильных устройств, Lighthouse и полного демо-сценария в браузере не запускалась. Перед защитой пройдите сценарий от отправки заявки до возврата автомобиля, проверьте печать демо-договора, размеры 360/390/768/1024/1440 px и клавиатурную навигацию.
